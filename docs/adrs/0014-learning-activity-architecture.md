# ADR 0014: Exercise files retain identity; learning activities own purpose and presentation

Status: accepted · 2026-08-14

## Context

The learner and Redaction both treated one exercise YAML file as one equally important activity.
That accidental equivalence made the course look arbitrary. Forty-nine topics own 168 practice or
drill files: a stable primary set, focused extensions, production scenarios, listening artifacts
and targeted drills all appeared as peer cards even though they do different jobs.

The old profile then judged every `practice` file by one generic rule: 8–15 items and at least three
item types. It consequently reported 86 small sets and 50 narrow sets. Forty-one of those sets are
deliberately two-question listening artifacts; many others are short production or document tasks.
Adding their item counts together would hide the false positives, not repair the model. Inferring
the lesson stage from `role` also labelled every practice file `geruest`, so 48 topics appeared to
have no transfer even when they owned an explicit production mission.

Exercise-set and item ids are already persisted in learner attempts, and probe arming refers to the
exact `<set-id>::<item-id>` pair. Renaming, merging or moving the current files would therefore
discard or detach real learning evidence. The content needs a semantic migration, not a filesystem
tidying exercise.

## Decision

An exercise file remains the stable storage and evidence unit. A **learning activity** is the
learner-facing purpose by which those files are organised. Every topic-owned `practice` or `drill`
set explicitly declares:

- `activity`: `core`, `extension`, `application` or `remediation`;
- `stage`: its authored place in the lesson cycle;
- `title_de` (or the existing B1 `title.de`): a concise German activity title.

The four dimensions remain independent and visible:

- `role` controls runtime and evidence semantics;
- `stage` states learning intent (`geruest`, `ausblenden` or `transfer` here);
- `activity` names the pedagogical purpose and controls grouping;
- `primary_practice` in the topic manifest controls Lernpfad completion.

Each topic has exactly one `core` activity: its `primary_practice`, with `role: practice` and
`stage: geruest`. An `application` is practice at `transfer`; a `remediation` activity is a drill at
`ausblenden`; an `extension` is practice at `geruest` or `ausblenden`. These are schema and
corpus-validation rules, not UI conventions.

The medium is a separate, derived dimension: `listening` when every item is `listen` or
`audio-comprehension`, `document` when the set carries a document stimulus, otherwise `mixed`.
Thus a two-question recording can be a complete transfer application, while a focused dictation is
an extension delivered through listening. “Hören” is never mistaken for a learning purpose merely
because it is a media type.

The learner page groups files by purpose: **Grundübung**, **Vertiefen**, **Anwenden** and **Gezielt
üben**. Listening and document tasks remain visibly labelled within the appropriate purpose. The
required core is the next action; optional groups use progressive disclosure. Redaction exposes the
same activity architecture and diagnoses broken contracts at the responsible file or topic.

There is no universal minimum item count or item-type count per file. The topic-wide outcome and
item-mix checks remain authoritative. The required core is held to 8–15 items; that band is not
applied to other purposes. A two-question listening check may be complete; a twelve-question
set may still be incoherent. Editors judge one explainable activity job, evidence for the declared
outcomes, cognitive load and transfer quality—not arithmetic alone.

`stage` records authored intent, while the runtime may deliver fading through mixed and adaptive
training. The absence of a dedicated `ausblenden` file therefore does not by itself mean that a
topic lacks fading. Redaction reports authored activities and runtime delivery separately.

## Consequences

The migration adds metadata and German titles to all 168 existing topic-owned sets. It then moves 21
productive items out of six overloaded cores, adds four coherent application files and nine new
fresh-context tasks, and updates manifests, probe arming and grading-decision references atomically.
Those moved items intentionally reset their test-profile evidence. The resulting corpus has 172
teaching sets, 49 cores inside the 8–15 band and a productive application for every topic. The page
can present a coherent activity plan even when several source files sit behind one group.

The old `set-zu-klein` and `set-zu-eng` findings disappear. Invalid activity contracts, an invalid
core or missing productive application are now validator failures; topic-wide evidence gaps remain
editorial diagnostics. Counts are generated by the activity audit rather than copied into product
claims.

This decision does not assert that every current item is pedagogically sound. Classification is the
start of the content audit, not proof that a file deserves to survive. Because the current learner
cohort is one consenting test profile, course quality takes priority over preserving its exercise
history; no id-alias mechanism is required for this normalization wave.
