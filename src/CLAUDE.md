# src/ — the learner app

Claude Code loads this file when you work in this directory; the root [`CLAUDE.md`](../CLAUDE.md) applies too. Language rules for rendering code (`pickSecond`, no `en · ru`) are under *Bilingual voice* in [`content/CLAUDE.md`](../content/CLAUDE.md).

## Runtime invariants

Load-bearing, and each one silent when broken. Mechanism: [`docs/architecture/runtime-contracts.md`](../docs/architecture/runtime-contracts.md).

- **`planReview()` (`src/lib/decks.ts`) is the ONE rule for what a review queue contains.** New cards are rationed **per day, not per queue** (`DAILY_NEW_CARDS = 15`), because `planReview` re-runs on every mount. Fresh-card ties break at random, never by card id.
- **A page header never repeats the navigation.** An H1 the active tab, nav link or breadcrumb already says is `sr-only`; a page's "what this is for" line is its nav link's `title` (`src/lib/nav-hints.ts`), never a standing paragraph. Content titles stay. → [`docs/overview.md`](../docs/overview.md#page-chrome)
- **A missed card is retried later, not next.** "Again" shows the answer at once and re-queues the card after 8 cards (not retrieved at all) or 50 (a lapse or near miss), halved per further miss, floor 3 — `recordMiss` in `src/lib/requeue.ts`. The counts are heuristics; the delay is the finding. FSRS alone schedules across sessions. A missed LiD question follows the same rule.
- **A page never inlines the corpus.** The session pages pass `corpusUrl('cards' | 'sets')` and fetch content-hashed `data/*.json` files ([ADR 0008](../docs/adrs/0008-delivery-static-site-desktop-shell-worker.md)); an island never mounts on a file that has not arrived. `bun scripts/page-weight.ts` fails CI on any page over 1.5 MB.
- **Never mount a React island per table row.** In `.astro` templates use `src/components/SpeakButton.astro` — one hoisted, delegated listener for the whole page.
- **Probe state is derived from the attempt log, never stored.** A due probe opens the session as step 0, *before* review and training. `MAX_PROBES_PER_SESSION = 5`.
- **Checkpoints and placements are data, not wiring** — discovered by role, level read off the directory; one of each per level.
- **A passed placement is a third evidence class**: green, real, and it **never raises the measured tier**. No placement branch in `topicTier`/`effectiveTier`; never fold placed topics into a mastery counter; no fifth chip in `EvidenceChips`. Nothing is written until the learner presses *Ergebnis übernehmen*.
- **Navigation asks a different question than the badge.** `pathDone` is mastered *or* primary practice completed *or* self-rated `learned`. **Never derive a badge from `pathDone`** — a self-rating is not evidence — and never gate the path on item-level completion alone.
- **Unverified practice never raises measured mastery.** `write` and `speak` are attempt → model answer → done; their `requirements`/`checklist` render as guidance, **never as gated forms**.
- **There is no default profile and no name is ever assumed.** Nothing may create a database before discovery has run. The last remaining profile cannot be deleted. An OAuth display name may only *prefill* the first-run field.
- **Every figure on `/about` is computed from content at build time.** Never hand-write a count there, and never claim a level is more finished than it is.
- Legacy or mismatched-revision attempts keep their logged result and are **never replayed** against a current key. Snapshot migrations v1–v8 are explicit (`src/lib/snapshot-schema.ts`).
- **No input is sized, capped or captioned from the answer it is waiting for.** Every cloze gap rests at one width and grows with what the **learner** typed (`gapWidthCh`, `Cloze.tsx`); `maxLength`, `placeholder` and `size` are the same hazard — a box sized to the answer scores a width judgement as grammar. No gate can see this class.
- **A progress write is journaled before it is attempted, and loud when late; a stalled or implausibly empty read renders an error, never a fresh-profile view, and never feeds `planReview`.** Every write behind the journal or `withPersistenceRetry` must be idempotent — the managed store re-runs an aborted operation up to three times, and launch replay re-applies whatever outlived its commit. No snapshot writer ever shrinks an existing file. **A write that commits after its caller's 45 s deadline still confirms itself**: the journal drain keeps owning the op and removes its entry when the commit lands. → [ADR 0006](../docs/adrs/0006-local-first-durable-learner-state.md), [0019](../docs/adrs/0006-local-first-durable-learner-state.md), [0020](../docs/adrs/0006-local-first-durable-learner-state.md)
- **One readwrite transaction on `progress` at a time; a burst of writes is ONE commit, not N; a stalled transaction is aborted, never abandoned.** `enqueueUpdate` coalesces, and the runner awaits every batch to its end. `src/lib/managed-store.ts` owns connection and transaction: a 10 s watchdog calls `abort()`, a retry waits for the abort to be *observed*, and an open that misses its 2 s deadline is retired and closed if it lands. An unacknowledged abort or a third failure blocks the store until restart (`StorageRestartRequiredError`; nothing auto-reloads). Grades, attempts and session completion share **one ordered journal drain per profile**; a caller's clock starts when it submits. Only a `TypeError`/`RangeError` is quarantined to `da:journal-poison:<profileId>`, after its evidence is saved; storage errors stay pending, overflow never discards an entry, and a refused localStorage write keeps a volatile copy and says so. → [ADR 0006](../docs/adrs/0006-local-first-durable-learner-state.md)
- **Reads get the same timed retries writes do, and every load surface distinguishes still-reading from read-failed from confirmed-empty.** All through `withReadRetry(op, { surface })` (0/2/5 s, `StoreStallError` at 10 s, stalls logged to `da:stall-log:<profileId>` as counters); a read that *rejects* is not retried. A progress surface renders `ProgressLoadError` with a retry; a badge renders an explicit unknown — **never a confident `0`**. **Nothing may sit between `getStore()` and its handle** (the card-id migration has one owner, `PersistenceAlert`, behind `da:cardid-migrated:<id>`), and **a repair that rewrites a whole blob commits in one `update()`**. → [ADR 0006](../docs/adrs/0006-local-first-durable-learner-state.md)
- `localStorage` keys with persisted user choices (e.g. `da:topics-view`) — **migrate old values** rather than stranding a learner on a state that no longer exists.
